# SwoftLang for VS Code

Language support and a **live execution tracer** for the SwoftLang (`.sw`)
scripting language.

## Features

### Language support (works offline, no server needed)

- **Syntax highlighting** via the shared TextMate grammar
  (`syntaxes/swoftlang.tmLanguage.json`, copied from the docs site so the two
  never drift).
- **Diagnostics** — the language server debounces (~300 ms) and runs
  `swoftc check` on the live buffer (written to a temp file), parsing both the
  `file:line:col: error|warning: msg` stderr lines and the
  `{"error":{message,line,col}}` stdout JSON into squiggles. Warnings render as
  warnings, errors as errors, and diagnostics clear when the file is clean.
- **Completion** — keywords, declaration openers, word operators, types,
  constants, builtins (with signatures), event names, property names and enum
  members. Context-light: the full set is always offered.
- **Hover** — builtins show their signature(s) + a one-line doc; properties show
  `Owner.name: Type` and read-only-ness.
- **Document symbols / outline / breadcrumbs** — `command`, `event`,
  `function` / `async function`, `gui`, `scoreboard`, `tablist`, `bossbar`,
  `mob` and `item` declarations.

Completion/hover data lives in `data/swoftlang-symbols.json`, generated by
`scripts/gen-symbols.js` from the grammar, `compiler/lib/registry.ml` and
`swoftc --property-table`. Regenerate with `npm run gen-symbols`.

### Live debug tracer (the special feature)

When the SwoftLang server is started with `--debug`, it hosts a WebSocket on
`ws://localhost:<debugPort>` (default `25580`) and streams execution events.
The extension connects and turns them into editor decorations:

- Each executed statement makes its line **flash bright emerald**, then fade
  over ~700 ms, leaving a fainter trail for ~2.5 s — so you literally watch a
  handler run line-by-line.
- Entering a handler drops a gutter marker (`◀ handler`) and a `▶ event Name`
  status message, so you see which handler fired.
- Hot-reload results surface as toasts (`reloaded chat.sw ✓` or the error), and
  the status-bar item shows connected/disconnected + the last reload result.

The extension is a pure **client** — it never pushes edits. The server watches
`scriptsDir` and reloads on save; you just save and watch the result.

## Requirements

- The `swoftc` compiler binary, resolved in this order:
  1. `swoftlang.swoftcPath` setting
  2. `SWOFTC` environment variable
  3. `swoftc` on `PATH`
  4. `<workspaceFolder>/compiler/_build/default/bin/main.exe`
- For the tracer: a SwoftLang server started with `--debug` (Part 3, server
  side). Until that exists, use the bundled mock (below).

## Settings

| Setting | Default | Meaning |
| --- | --- | --- |
| `swoftlang.swoftcPath` | `""` | Path to the `swoftc` binary. |
| `swoftlang.debugPort` | `25580` | Debug WebSocket port. |
| `swoftlang.scriptsDir` | `""` | Base for the server's `scripts/…` paths (falls back to `hello.scriptsDir`, then `<ws>/scripts`). |
| `swoftlang.debug.autoConnect` | `false` | Connect to the debug server on activation. |
| `swoftlang.debug.autoReveal` | `true` | Open+reveal a file when a trace arrives for it. |

## Commands

- **SwoftLang: Connect to Debug Server**
- **SwoftLang: Disconnect from Debug Server**

(also reachable by clicking the status-bar item)

## Running it

```bash
npm install
npm run compile        # tsc -> out/
# optional, produces a .vsix:
npm run package        # -> vscode-swoftlang.vsix
```

- **From source (F5):** open this folder in VS Code and press **F5** to launch
  an Extension Development Host with the extension loaded. Open any `.sw` file.
- **From the .vsix:** `code --install-extension vscode-swoftlang.vsix`.

## Demoing the tracer with the mock server

The mock (`test/mock-debug-server.ts`) speaks the exact protocol without needing
the Java side. It emits `hello`, a handler enter, a few trace lines stepping
through the `event PlayerBeginItemUse` block in `scripts/events.sw`, a handler
exit, a successful reload and a failed reload.

```bash
npm run compile
npm run mock           # listens on ws://localhost:25580
```

Then in the Extension Development Host: open `scripts/events.sw`, run
**SwoftLang: Connect to Debug Server**, and watch lines 17/18/20 flash in
sequence followed by the reload toasts.

Environment knobs for the mock: `PORT`, `SCRIPTS_DIR`, `TRACE_FILE`, `STEP_MS`,
`LOOP=1` (repeat forever).

## Protocol (server → client, newline-delimited JSON)

```jsonc
{"type":"hello","protocol":1,"scriptsDir":"/abs/path/scripts"}
{"type":"trace","file":"scripts/chat.sw","line":12,"col":9,"kind":"send","handler":"event PlayerChat","seq":42,"ts":<ms>}
{"type":"handler","phase":"enter"|"exit","file":"scripts/chat.sw","line":11,"name":"event PlayerChat"}
{"type":"reload","file":"scripts/chat.sw","ok":true}
{"type":"reload","file":"scripts/chat.sw","ok":false,"error":"chat.sw:4:9: error: ..."}
```

Client → server (optional; the server streams by default on connect):

```jsonc
{"type":"subscribe"}
```

`line`/`col` are **1-based** (compiler convention); the client subtracts one for
0-based editor positions.

## Layout

```
vscode-swoftlang/
├─ package.json               extension manifest (languages, grammar, settings, commands)
├─ language-configuration.json
├─ tsconfig.json
├─ syntaxes/swoftlang.tmLanguage.json   (copied from docs/.vitepress)
├─ data/swoftlang-symbols.json          (generated; completion + hover data)
├─ scripts/gen-symbols.js               (regenerates the data file)
├─ src/
│  ├─ extension.ts           client: LSP launch + tracer wiring + commands
│  ├─ server.ts              LSP: diagnostics / completion / hover / symbols
│  └─ tracer.ts              WebSocket tracer client + editor decorations
└─ test/
   ├─ mock-debug-server.ts   scripted mock server (npm run mock)
   ├─ headless-diag-test.js
   └─ headless-tracer-test.js
```
